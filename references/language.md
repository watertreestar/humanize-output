# 语言与信息质量

当主要问题是措辞、语气、信息密度或模板化表达时读取本文件。规则适用于中文及其他语言；示例用于帮助判断，不是禁词表。

## 常见信号

- 开头先讲读者已经知道的大背景，迟迟没有进入答案。
- 用“至关重要”“显著提升”“全面赋能”“无缝体验”等抽象判断代替机制、后果或证据。
- 句子语法没有错误，但明显受英文结构影响，不符合目标读者的自然表达习惯。
- 同一个观点被换成多个近义句，又在小结或“核心要点”中重复一次。
- 每个观点篇幅和语气完全一致，导致真正重要的决策或风险不突出。
- 为了显得专业而连续堆叠术语，却没有提高准确性。
- 肯定语气掩盖了证据缺失、不确定性或未经说明的假设。
- 标题、分点、冒号、破折号或三段式结构只是习惯性出现，没有帮助阅读。
- 把普通进展包装成宏大转型，把简单问题写成营销文案。

## 修改方法

1. 尽早说清决定、答案、现象或具体场景。
2. 把表示“重要”和“优秀”的形容词换成机制、后果、实例或可验证指标。
3. 合并重复观点，删除目标读者不需要的铺垫。
4. 保留行业内准确且自然的术语，只在读者确实需要时解释。
5. 让结构服从内容：连续论述可用短段落，重复字段比较才适合表格，步骤和并列项才适合列表。
6. 如实保留不确定性，区分事实、推断、估算、目标和待确认事项。
7. 修改整句话表达的思想，不要只把命中的词机械换成另一个词。

## 中文专项检查

- 检查英文名词化结构是否被硬译成“对……的……”，能否改为直接的主谓表达。
- 检查“进行、实现、打造、构建、赋能、助力”等动词是否掩盖了真正动作。
- 检查“不仅……更……”“这不仅是……而是……”是否真的存在需要强调的对比。
- 检查“首先、其次、此外、最后”是否承担逻辑作用，而不是为了凑齐段落。
- 检查“闭环、抓手、底座、矩阵、方法论”等词是否为目标读者提供了准确含义。

这些表达在合适语境中都可以保留。例如，数学中的“收敛”、机器学习中的“门控”、业务管理中的“闭环”可能具有准确含义。判断依据是上下文和读者，而不是词本身。

## 上下文豁免

- 某个短语经常被 AI 使用，不代表它在当前文本中必然有问题。
- 法律、政策、学术或管理场景需要正式语言时，应优先保持准确性。
- 安全说明、参考文档或相互独立的 UI 状态可能需要适当重复。
- 项目可能强制使用统一模板；此时应改进模板中的内容，而不是擅自破坏规范。

## 使用中文规则检查器

需要检查较长的 Markdown、Issue 或文档时，可以运行：

```text
python scripts/humanize_lint.py <文件> [<更多文件> ...]
```

规则位于 `data/zh-output-smells.json`。输出会显示严重性、命中位置、原因、修改方向和专业语境说明。默认只让 P1 导致非零退出；P2 和 P3 用于人工复核。

把检查结果当成候选问题：

1. 先看整句和目标读者，再判断是否修改。
2. 专业术语命中时先查看语境说明；准确术语不应为了“清零”而替换。
3. 同一句有多个命中时，优先重写它表达的思想，不要逐词替换。
4. 规则没有命中不代表内容正确，事实、证据、结构和可执行性仍需人工审查。
