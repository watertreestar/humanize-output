# UI/UX 与产品设计

界面需要让真实业务流程中的信息、状态、层级和操作清晰可见。看起来像一套精致的 SaaS 模板，并不能证明产品可用。

## 审查要点

- 明确主要用户、高频任务、判断顺序和实际操作约束。
- 页面围绕业务流程与信息优先级组织，不默认使用大标题区加多张功能卡片的布局。
- 只有相互独立、需要比较或可以移动的内容才适合放入卡片；不要给每一块内容都加圆角容器。
- 渐变、图标、胶囊标签、圆角、阴影和动效应服务于品牌、分组、状态或交互反馈，而不是单纯制造“现代感”。
- 数据密度应匹配任务。管理后台和监控页面往往需要紧凑表格、筛选、批量操作和持续可见的上下文。
- 根据场景设计加载、空数据、错误、部分成功、禁用、选中、成功、无权限和数据过期等状态。
- 检查键盘操作、焦点、对比度、非颜色提示、点击区域、减少动态效果、长文本、多语言和窄屏表现。
- 使用可信的标签和数据。不要添加看起来有说服力但没有来源的指标。

## 业务后台专项检查

- 常用筛选和主要操作是否在首屏可达？
- 表格列是否按照判断顺序排列，而不是平均分配宽度？
- 批量操作是否说明选中数量、影响范围、权限、不可处理项和部分失败结果？
- 高风险或不可逆操作是否有与风险相称的确认，而不是所有按钮都弹窗？
- 操作完成后，用户能否知道成功了什么、失败了什么以及下一步怎么办？

## 解释设计决策

说明布局和组件为什么适合当前流程，不要把个人审美写成普遍规律。常见字体、卡片、渐变和成熟交互模式在符合上下文且有明确用途时完全可以使用。
