# 演示文稿与项目总结

演示文稿应帮助听众理解、决定或行动。每一页都要承担论证中的具体任务，而不是只占据标准故事线中的一个位置。

## 审查要点

- 先确认材料用于现场讲解、独立阅读、决策、培训还是进度汇报。
- 每页只承担一个主要信息；需要推动结论时，标题应表达观点而不只是写“市场分析”“项目成果”。
- 根据内容重要性调整版式，不要每页都使用“标题加三个分点”。
- 优先使用证据、图表、流程图、真实界面、决策和具体案例，少用装饰性图标与无关素材。
- 所有指标都要说明来源、时间、口径，以及它是实际值、估算值、行业基准还是目标值。
- 幻灯片需要便于扫读；必要的细节可放入演讲者备注，不要全部挤在页面上。
- 结尾应给出需要的决定、负责人、下一步或待解决问题，而不是只写“谢谢”或重复总结。

项目总结要区分已完成的工作、实际测得的结果、尚未解决的风险和下一项决策。不要把常规交付包装成没有证据的“全面升级”或“战略转型”。
