# 文档

文档应该减少读者完成正确操作或建立正确理解所需的时间。结构应跟随读者的使用过程，而不是套用一份通用目录。

## 审查要点

- 明确读者是谁，以及读者打开文档时要完成什么任务。
- 尽早给出前置条件、最短可用路径和预期结果。
- 命令、示例、路径、版本和命名要符合实际平台、仓库及项目约定。
- 在真正影响使用的地方说明限制、常见失败和恢复方法。
- 不要解释目标读者早已知道的基础概念，也不要为了显得完整而增加空章节。
- 同一个事实保留一个权威说明位置，避免在概述、注意事项和总结中反复改写。
- 条件允许时验证链接、命令、API 名称、参数、代码示例和兼容性声明。
- 开头应尽快解决读者的主要问题；结尾只有在能补充决策、后续动作或关键限制时才保留。

## API 与参考资料

把规范行为和示例分开。明确类型、默认值、单位、错误情况和版本假设。不要为了让示例看起来完整而虚构接口、字段或响应；未知内容应明确标注为待确认。
